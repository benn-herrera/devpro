# A stand-in models the API's real semantics

Code that stands in for another piece's behavior — doctor's `devpro:` line naming the command that
runs it, a runner's stub of a host's surface — models that behavior's
semantics as they stand, and moves with them: a change to the real semantics changes the stand-in in
the same change, and the residue of the former semantics — a probe the code no longer runs, a
search it no longer makes — leaves with the semantics it served ([Obviated code is deleted, not
parked](obviated-code-is-deleted-not-parked.md)). A stand-in left answering by the
former semantics reports a state the real mechanism cannot reach, and whoever reads it acts on a run
that will not happen.
